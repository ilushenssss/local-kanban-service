Пользователь создаёт карточку TeamSync, вводя только ID задачи Redmine. Python загружает поля ТИ, затем по этому же ID находит КРИС_ТИ и её подзадачи. Bugzilla подключается на следующем этапе для сверки багов.

Как создаётся карточка

  1. Пользователь нажимает «Новая задача» и вводит ID из адреса Redmine /issues/23018.
  2. TeamSync загружает номер ТИ, заголовок, статус, согласования отделов, основание и номера багов. ID задачи и номер ТИ могут различаться: например, 23018 и ТИ-1157.
  3. В проекте КРИС_ТИ TeamSync ищет задачу, у которой поле «Расположение ТИ» указывает на исходный ID 23018. Затем по собственному ID найденной КРИС_ТИ получает её подзадачи и статусы.
  4. TeamSync добавляет карточку в колонку, соответствующую статусу ТИ. Поля заполняются из Redmine автоматически.

Python-клиент Redmine

Вход
URL Redmine, учётные данные пользователя и ID выбранной задачи ТИ.
Чтение
rm = Redmine(url, username=login, password=password), затем rm.auth(). Получение задачи и связанных данных через rm.issue.get() и rm.issue.filter(). Запросы выполняются в фоновом потоке PyQt.
Выход
Исходные поля Redmine или результат ошибки для каждого запроса. Повторное обновление заново читает источник.

ТИ и редакции ТИ

Вход
ID задачи Redmine для вызова rm.issue.get(issue_id).
Выход
ID Redmine, номер ТИ, заголовок, текущий статус, согласования отделов, основание, список номеров багов и время обновления. Эти номера выводятся на карточке сразу, а позже используются для сверки с Bugzilla.
Уточнить
Технические ID пользовательских полей в Redmine и формат значений основания, согласований и списка багов.

КРИС_ТИ и подзадачи

  1. В проекте КРИС_ТИ искать точное совпадение исходного ID задачи Redmine в поле «Расположение ТИ». Если поле хранит ссылку, сравнивать ID из ссылки. Уточнить ID пользовательского поля, формат значения и доступность фильтрации через API.
  2. Для прямых подзадач выполнить rm.issue.filter(parent_id=kris_id, status_id="*"). Получить текущий статус каждой подзадачи. Согласовать уровни вложенности и набор статусов, считающихся завершёнными.
  3. Передать список подзадач и прогресс завершено / всего. Отдельно обозначать отсутствие связи, несколько совпадений и отсутствие подзадач.

Согласования отделов

Вход
Номер ТИ и подтверждённый источник в Redmine.
Выход
Отдел, исходный статус, статус для отображения и время последнего получения. Например: ОСП — «На согласовании», ОСЗ — «Согласовано».
Уточнить
Где хранятся решения и как выбирать актуальное среди нескольких записей. Для отсутствующих сведений показывать «Нет данных».

Python-клиент Bugzilla · следующий этап

Вход
Логический номер ТИ, адрес Bugzilla и параметры авторизации установки.
Чтение
Python выполняет HTTP GET в Bugzilla REST API. Отбор идёт по полю «Номер ТИ». Техническое имя поля и поддерживаемый способ поиска нужно подтвердить на вашей установке.
Выход
Номера доступных багов после удаления повторов и признак успешной загрузки.

Сборка карточки в Python

  1. Хранить отдельно числовой ID задачи Redmine для связи через «Расположение ТИ» и номер ТИ для отображения и будущей сверки с Bugzilla.
  2. Сформировать данные доски и окна задачи: статус ТИ, согласования, основание, номера багов, статусы подзадач, прогресс КРИС_ТИ и время получения.
  3. На этапе Bugzilla сравнить каждый полученный ID бага с номерами в соответствующей ТИ. Совпадение — зелёный, отсутствие после успешной проверки — красный, ошибка загрузки или недоступное поле — нейтральный.

Доска и окно задачи TeamSync

  • Статус ТИ выбирает колонку. В карточку выводятся название, прохождение КРИС_ТИ и статусы отделов. В окне задачи доступны сведения из карточки и детализация, которую возвращает источник.
  • Пустой ответ, отсутствие прав и сбой сети отображаются отдельно. Если есть ранее загруженные данные, при сбое показывается время их последнего успешного обновления.
  • Первый этап создаёт карточку в TeamSync и читает данные из Redmine. Если исходная задача недоступна, карточка не создаётся. Если КРИС_ТИ не найдена или недоступна, поля ТИ сохраняются, а блок КРИС_ТИ показывает причину. HTML-макет имитирует загрузку по номеру 23018 на условных данных.

Из исходного эскиза · уточнить

«Страница текущей версии», «Неосмеченные баги и СП» и «Страница ИД» относятся к будущим экранам. Сопоставление СППИ ЛиП, СП и ИД, а также источник согласования отдельных приложений требуют отдельного описания.
