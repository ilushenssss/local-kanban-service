# Контракт поведения

Источник бизнес-решений: `docs/ARCHITECTURE.md`, согласованные пользователем требования. Роли и проверка входа отложены, архивирование вместо удаления. Никаких серверных разрешений в файловой версии нет.

Создание и изменение задачи используют одну форму, после успешного сохранения она закрывается. Комментарии/вложения требуют сохранённой задачи. Редактирование блокируется только на время её операции; размеры и названия кнопок не меняются. Поля сохраняются при ошибке; повтор использует прежний UUID. Конфликт явно показывает текущую версию и сохраняет пользовательскую форму. Принятие новой версии как основы требует подтверждения, автоматического перезаписывания нет.

Закрытие и Escape предупреждают о несохранённых полях, комментарии, загрузках и неопределённом результате. Во время фоновой операции окно не закрывается. Долговременных черновиков на диске нет.

Архивирование доски/задачи подтверждается, по умолчанию выбрана отмена. Задачи можно восстановить через фильтр «Архив». Задачи физически не удаляются; история не очищается. Колонка удаляется только с выбором оставшейся колонки для всех её задач, включая архивные. Подтверждение по умолчанию — отмена; изменение применяется после сохранения настроек. Перенос и история атомарны; версия задачи повышается. Последнюю колонку удалить нельзя.

Поиск 300 мс, ответы старой выборки игнорируются. Точное имя исполнителя, точная метка, диапазон дат, приоритет и быстрые фильтры совместно применяются по БД. Текущий набор отображается полностью, прокрутка нативная. Открытые формы не заменяются при фоновом обновлении.

Весь принадлежащий приложению текст русский; нативные файловые диалоги и стандартные системные сообщения зависят от локали ОС. Время истории отображается в часовом поясе команды, срок — календарная дата. Просрочка обозначена словом «Просрочено». Ввод длинных полей доступен в прокручиваемой форме, управление перетаскиванием имеет кнопочную альтернативу.

Встроенные Qt controls владеют focus, keyboard, selection и popup; пользовательские HTML/ARIA-компоненты не применяются. Проверка окон, состояния ошибок, конфликта, клавиатуры и поиска — `tests/test_ui.py`. Полная проверка доступности в Windows не выполнена.


Справочники сотрудников и меток хранятся в общей БД. Добавление и изменение отображаемого имени сотрудника — `CatalogDialog`, login неизменен при переименовании. Удаления нет. Метки добавляются для текущей доски. Оба справочника используют RegistrySelection: обычный Qt combo по щелчку/стрелкам/Enter добавляет значение в расположенный ниже список выбранного, Escape отменяет выбор. Выбранное значение не предлагается повторно; «Убрать» снимает назначение/метку и возвращает её в выпадающий список. Никаких имён и меток через запятую в форме больше нет.

DateField: стандартный QDateEdit шириной 160 с русским выпадающим календарём по стрелке, без предварительного включения. «Без срока» означает отсутствие даты; «Сбросить» очищает её. Пустое поле открывает текущий месяц и не назначает дату при Escape. Отображение dd.MM.yyyy, хранение ISO date. ChecklistEditor: кнопка/Enter добавляет пункт, флажок отмечает, двойной щелчок редактирует, кнопка удаляет выбранное; незавершённый ввод включается при сохранении задачи. Enter в строке пункта не сохраняет задачу. При закрытии незавершённый пункт считается несохранёнными данными.

Создание задачи использует первую колонку доски без поля переноса. Перенос выполняется на доске перетаскиванием или контекстным меню; поле переноса в форме скрыто. Успех закрывает форму; ошибка и конфликт сохраняют её. Если после неопределённого commit внесены новые правки или остались неотправленный комментарий/файлы, подтверждение прежней записи не закрывает окно с этими данными.

История — экранированное читаемое представление неизменяемых событий, русские поля, текущие имена сотрудников/колонок, прежнее → новое. Приоритеты подписаны и имеют отдельные семантические цвета в списках и на карточках.

Статистика не зависит от фильтров и исключает архивные задачи. Несколько исполнителей учитываются каждый отдельно. Тема локальная, светлая/тёмная; единая палитра распространяется на открытые формы.

Обновление доски: раз в 5 секунд читается актуальное состояние, но неизменившиеся данные не пересоздают виджеты. Во время QDrag обновления откладываются, включая результаты уже запущенного чтения. После выхода из цикла перетаскивания выполняется свежее чтение. Начало записи инвалидирует прежние ответы. QDrag не удаляет строки модели автоматически: перенос выполняет Store, после чего обновляется представление.

История отображается от старых событий к новым. Комментарии оформлены как переписка; автор определяется по login, не по отображаемому имени. Введённые строки экранируются перед HTML-отображением. Завершённые задачи имеют зачёркнутый заголовок и приглушённое содержимое. Пустая строка состояния не занимает место.

Версия 1.5: доски переключаются верхним QTabBar, идентификаторы сохранены в tabData; обновление без изменений не пересоздаёт вкладки. «Мои задачи» запрашивает назначения текущего login по всем активным доскам независимо от фильтров канбана. Личные поиск/фильтры действуют по полному набору назначений. Открытие строки получает колонки её доски асинхронно, выбранная доска не подменяет данные задачи.

Версия 1.6: sidebar сворачивается; клик на карточке открывает задачу с постоянным чатом рядом. На узком окне чат располагается ниже формы. Системные записи читаются из task_history и не редактируются. Счётчик показывает только непрочитанные чужие комментарии. Для отметки чтения используется максимальный ID из уже загруженного и видимого чата, а не ID новых сообщений, пришедших позже. Старые отметки не уменьшают текущую. Список и Гант используют тот же полный фильтр доски; диаграмма только для просмотра. Нативные popup и календарь остаются прежними.

Версия 2.0: скрытые QTabBar хранят идентификаторы досок для совместимости, но не отображаются. Вид выбирается через view_switch, синхронный с pages. Дерево — единственный видимый список досок, имена «Проект / Доска» группируются без новой модели данных. Основные фильтры видимы сразу, остальные раскрываются. Архивирование задачи в контекстном меню. Нижних растянутых кнопок нет.

Версия 2.1: повторный выбор активной доски явно возвращает из «Моих задач» в канбан. Форма задачи не имеет общей вертикальной полосы, длинное содержимое прокручивается внутри собственных полей. В обсуждении первое открытие прокручивает вниз; чтение старых сообщений не прерывается обновлением.

Messenger — общий чат сотрудников. Кнопка справа снизу показывает чужие непрочитанные сообщения. Открытие ведёт к концу переписки; отметка чтения сохраняется только у видимой панели в нижней позиции. Ошибка отправки сохраняет текст и UUID, повтор не дублирует запись. Если во время неопределённого результата введён новый текст, подтверждение прежней отправки не очищает новый черновик. Сворачивание не удаляет черновик, выход с ним требует подтверждения. Общий чат не влияет на задачу и её версию.


## Согласованная визуальная переработка по HTML-макетам

Внешний вид обновляется по трём макетам. Явное сохранение и история сохраняются; успешное сохранение закрывает форму, ошибка/конфликт сохраняют ввод. Надпись «Данные хранятся только на этом устройстве» не добавляется. Новые операции удаления, времени срока и календаря не вводятся в визуальную задачу. Изменение расположения вкладок выполняется на отдельном экранном этапе.


Уточнение: в форме создания и редактирования задачи нет кнопок открытия справочников; существующие сотрудники и метки выбираются через RegistrySelection. Создание записей справочников выполняется отдельно в основном окне. Действия интерфейса имеют текстовые подписи, без декоративных значков и эмодзи. Сохранение и история остаются доступны.


Общий чат и обсуждение задачи: Enter (включая цифровую клавиатуру) отправляет сообщение, Shift+Enter добавляет строку. Пустой текст, автоповтор клавиши и активная IME-композиция не отправляются. Используется существующая кнопка отправки с её блокировками и безопасным повтором. Enter в описании задачи сохраняет обычное многострочное поведение.


## Выбор срока и приоритета

Срок открывает существующий Qt-календарь при клике в любой части поля, включая текст. Прямой ввод цифр и прокрутка колеса в закрытом поле не меняют дату. Space/Enter/стрелка вниз открывают календарь; его стандартное клавиатурное управление сохраняется. Пустой срок показывает текущий месяц; Escape не назначает дату. «Сбросить» очищает значение. Дата хранится в прежнем ISO-формате.

Приоритет задачи — список радиокнопок, выбран ровно один из четырёх существующих вариантов. Значения и сохранение в БД не меняются. Меню колонок остаётся в настройках доски, отдельных кнопок «Изменить» в колонках нет. Кнопки чата и сворачивания меню имеют значки и доступные русские имена/подсказки.


Главная точка входа всегда открывает основное окно через showMaximized(): на весь доступный рабочий стол, с системными кнопками сворачивания, восстановления и закрытия. Пользователь может затем уменьшить окно. Начальное состояние не зависит от последнего размера предыдущего запуска.


Подробности на доске: шеврон внизу карточки раскрывает описание, участников и чек-лист без открытия редактора и без записи в БД. Пробел переключает раскрытие выбранной карточки; Enter открывает редактор. Состояние хранится в окне по ID задачи и сохраняется при фоновом обновлении. Длинные подробности ограничены по высоте; полное содержимое доступно в редакторе. Перетаскивание и существующая защита конфликтов сохраняются.

## Роли и доступ v3

Канонический экран управления доступом — AccessDialog в kanban/ui.py: QDialog + Async, QListWidget (флажки участников), нативный QComboBox роли/владельца, QFormLayout, общий button и текстовый статус. Использует тему kanban/theme.py без новых токенов. Загрузка блокирует сохранение; ошибка остаётся в окне, введённые значения при ошибке записи сохраняются. Изменение прав подтверждается QMessageBox с безопасным исходным выбором. Повторное сохранение ролей/членства задаёт желаемое состояние. Окно не закрывается во время записи. Роли и участники используют одну форму и одинаковую обратную связь. Административные пункты меню и создание задач блокируются по актуальным правам; Store повторно проверяет все операции. Матрица и миграция: ACCESS.md. Это расширение существующего стиля, визуальные токены не меняются.

## Фотостикеры v4

Messenger владеет предпросмотром, состоянием отправки и показом изображений. StickerInput расширяет существующий MessageEdit вставкой изображения из буфера; текстовая вставка и Enter сохраняют прежнее поведение. Выбор файла — нативный QFileDialog. Подготовка, запись и загрузка выполняются через существующий Async/work вне потока UI. Во время подготовки показывается статус; во время отправки кнопки блокируются без изменения размера. Ошибка сохраняет предпросмотр и текстовый черновик. Неопределённая запись повторяется тем же UUID и байтами; замена/снятие стикера до подтверждения запрещены.

Таймлайн — QTextBrowser с отключёнными внешними ссылками и загрузкой внешних ресурсов. PNG поступают только через проверенный Store.team_sticker и QTextDocument resources. Фотостикеры имеют автора, время и ссылку на нативный QDialog увеличенного просмотра с кнопкой «Закрыть». Общая тема и токены messenger/presentation переиспользуются; новых визуальных токенов нет. Для недоступного изображения показывается текст и повторяется загрузка; отметка прочтения не продвигается до получения изображения. Все три роли могут отправлять/читать стикеры в общем чате.

## Системные уведомления и орфография

Notifications — единый владелец QSystemTrayIcon, локальных переключателей и восстановления окна. Первый успешный опрос чата устанавливает начальный ID без уведомлений; дальнейшие ID обрабатываются один раз, собственные сообщения пропускаются. Очередь объединяется за 1200 мс, перед показом повторно проверяются настройки и активность чата. Нажатие восстанавливает окно с сохранением состояния развёртывания и открывает общий чат. Скрытие в трей сохраняет формы, черновики и таймеры. Явный выход использует прежние проверки несохранённых данных и останавливает таймеры. При недоступном трее закрытие окна остаётся обычным. Чат не отмечает сообщения прочитанными в свёрнутом или неактивном окне.

SpellTextEdit/SpellLineEdit и SpellItemDelegate в kanban/spellcheck.py — общие редакторы орфографии, MessageEdit наследует SpellTextEdit с прежней обработкой Enter/IME. Русская и английская морфология — локальные Hunspell-словари и встроенный Spylls. Словари читаются один раз в QThreadPool; результат и повторная подсветка доставляются в поток UI. QSyntaxHighlighter форматирует только отображение QTextDocument; QLineEdit рисует волну поверх стандартного редактора. Смещения многострочной подсветки переведены в UTF-16 (эмодзи не смещают подчёркивание). Цвет — существующий семантический danger из TOKENS, включая тёмную тему. Орфография не применяется к login, поиску и текстам только для чтения. Переключатель немедленно обновляет открытые редакторы. Новых визуальных токенов нет; меню/фокус/клавиатура остаются нативными Qt. Словари, лицензии и происхождение поставляются в kanban/dictionaries/ и kanban/_vendor/README.md.

## Чаты досок и метки v5

MainWindow.activate_board_chat выбирает отдельный экземпляр Messenger для каждой доски. Старый чат скрывается вместе со значком и останавливает опрос, сохраняя ввод, предпросмотр и состояние повторов. Отложенный ответ доставляется только экземпляру своей доски. При отзыве доступа кэш сообщений/изображений очищается. Общий Notifications опрашивает доступные доски, не зависит от выбранного чата и проверяет доступ перед показом; уведомление открывает нужную доску. Первый опрос не уведомляет о старой истории. Непрочитанные и отметки чтения независимы для каждой пары пользователь/доска. Заголовок чата показывает имя доски, без доски кнопки отправки выключены.

CatalogDialog остаётся канонической формой меток: QListWidget, QLineEdit, общие button/Async/текстовый статус. Переименование предварительно заполняет имя; пустое, занятое или изменённое другим клиентом имя отклоняется с сохранением ввода. Удаление подтверждается названием метки и числом затронутых задач. Кнопки/проверки Store учитывают manage; при загрузке/записи повторные действия блокируются. Переименование/удаление повышает версии связанных задач и записывает изменения labels в историю. UUID обеспечивает безопасный повтор удаления после неопределённого commit. Значения меток и назначения проверяются в одной транзакции. Новых компонентов и визуальных токенов нет.

## Раздел «Личное» v6

Навигация переиспользует существующий QTreeWidget: отдельная группа «Личное» содержит действие создания, только доски текущего пользователя и архив личных досок. Создание/восстановление использует прежние QInputDialog, Async и безопасную повторяемую запись; после успеха открывается соответствующая доска. Отмена диалога ничего не меняет, сетевой сбой сохраняет операцию для повтора. Пустое имя отклоняется Store. Группа доступна и пользователю без рабочих досок; создание рабочих досок остаётся ограничено общей ролью. В свёрнутой навигации группа скрывается вместе с деревом по прежнему правилу.

Настройки колонок, меток и задач личной доски используют существующие формы. Владелец получает manage/create/archive_task независимо от роли; «Участники доски» отключено. Личный архив не показывает чужие доски и позволяет восстановление. Архивирование подтверждается с объяснением восстановления. Никакие действия интерфейса не преобразуют рабочую доску в личную или обратно. Цвета, типографика, отступы и тема берутся из прежних владельцев в theme.py; новых визуальных токенов нет. Личные доски не видны другим пользователям даже в режиме администратора. Ограничение общего файлового хранения описано в README.md.

## Уведомления задач v7

Notifications остаётся единым владельцем QSystemTrayIcon и восстановления окна; QMenu получает независимый локальный переключатель уведомлений задач. Отдельный курсор task_cursor и очередь task_pending не смешиваются с чатом. Первый успешный snapshot пропускает старую историю; ошибки опроса не продвигают курсор. События объединяются за 1200 мс. Перед показом повторно проверяются права/активность доски; временная ошибка проверки возвращает события в очередь с повтором через 3 секунды, отказ в доступе удаляет их из очереди. Выключенная настройка не накапливает отложенные всплывающие сообщения.

task_notification_text в presentation.py строит краткий русский текст с номером/названием задачи, автором, назначением/снятием, новым статусом или изменёнными полями. Полный текст описаний и чек-листов остаётся внутри карточки; длинные названия сокращаются. Собственные действия не уведомляют. Карточка может быть открыта при активном приложении: задача, редактируемая другим человеком, не обновляется поверх несохранённых правок. Нажатие уведомления открывает TaskDialog через прежний асинхронный путь, проверяя доступ; существующая форма фокусируется с сохранением черновика. Уведомление объединённой группы открывает задачу последнего показанного события. Нативный QSystemTrayIcon не даёт отдельных ID для сохранённых Windows уведомлений: обработчик работает с последним показанным уведомлением. Тема и формы переиспользуются, новых визуальных токенов нет.

## Счётчики досок

QTreeWidget навигации имеет две колонки: название растягивается, колонка счётчика фиксирована (42px). BoardBadgeDelegate в kanban/board_badges.py владеет отрисовкой: нативный фон/выделение, круглая плашка высотой 20px, текст 11px, цвета существующих TOKENS danger/background. Новых визуальных токенов нет. Имя доски и ID не изменяются, длинное имя доступно в tooltip. Личные действия создания/архива занимают всю ширину строки. Счётчик пуст при нуле, 99+ при значении больше 99, точное число и разбивка доступны в tooltip обоих столбцов. Группы суммируют дочерние доски.

update_board_badges обновляет только существующие ячейки дерева, без перестройки канбана/дерева, смены выбора или сброса прокрутки. Фоновый Notifications.poll получает счётчики через тот же Async worker независимо от видимости чата и наличия системного трея. После перестройки списка досок кэшированные счётчики применяются повторно. Настройки системных уведомлений не отключают внутренние счётчики.

TaskDialog подтверждает только загруженный notification_cursor при активном видимом окне. render_extras/первый показ/активация используют один acknowledge_task_notifications; параллельные подтверждения блокируются, неуспех повторяется при следующем чтении. Скрытая/свёрнутая/неактивная форма ничего не подтверждает. Фокус уже открытой карточки через системное уведомление сохраняет черновик, обновляя только снимок уведомлений. Статусы прочтения не меняют версию/историю задачи и не создают новых уведомлений.


Колокольчик рядом с «Настройки» открывает список непрочитанных событий задач и сообщений чатов доступных досок. Карточка показывает счётчик только своих событий. Выбор уведомления ведёт в задачу или чат, где действует обычная отметка прочтения. Просмотр списка сам по себе ничего не помечает.

«Настройки» → «Часовой пояс…» доступен администратору. Пояс хранится в общей базе, применяется ко времени в задачах, чатах и уведомлениях. По умолчанию используется UTC. Хранимые метки времени записываются в UTC, сроки остаются календарными датами.
