# Проверки текущей версии

Проверено в облачной среде Linux, Python 3.12.14, PyQt5 5.15.11 / Qt 5.15.2. Никаких проверок в Windows или на SMB-сервере не выполнялось.

## Выполнено

- `QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v`: **22 теста, все прошли**. 15 тестов хранилища и 7 QtTest-проверок интерфейса.
- Основные операции, история и откат транзакции при ошибке, принадлежность колонки доске, архив/восстановление, завершение/повторное открытие, порядок колонок, фильтры и поиск кириллицы.
- Повтор создания задачи, комментария и вложения с тем же UUID не создаёт дубликатов; изменение тела запроса при том же UUID отклоняется.
- Конфликт двух версий задачи отклоняет устаревшую запись, сохраняет текст пользователя. QtTest проверяет сравнение доступно и открытая форма не заменяется фоновым обновлением.
- Имитация ошибки ПОСЛЕ успешной записи комментария: повтор не дублирует комментарий. То же для сохранения задачи: новые правки после ошибки остаются несохранёнными в форме и записываются отдельной операцией.
- Четыре дочерних процесса одновременно создают задачи на **локальном Linux-диске**: уникальные номера, все четыре записи сохранены.
- Файлы с одинаковым исходным именем хранятся отдельно; повтор загрузки не дублирует вложение; существующий файл назначения не заменяется. Отсутствующий/повреждённый файл вызывает ошибку.
- Повторное резервирование, integrity_check/foreign_key_check, контрольные суммы, восстановление в новый каталог; существующий каталог восстановления не заменяется.
- QtTest: сохранение клавиатурой, поиск/пустая выборка, перемещение кнопочным обработчиком, предупреждение при Escape, конфликт, фоновые обновления, повтор после ошибки. Снимки реальных Qt-виджетов с offscreen-платформой: `screenshots/board-linux.png`, `board-narrow-linux.png`, `task-linux.png`; просмотрены визуально.
- `.venv/bin/python -m pip check`: конфликтов зависимостей нет.
- Исходники разобраны парсером с грамматикой Python 3.8; это не запуск под Python 3.8.
- `tools/build_windows.py` выполнен: официальные Python 3.8.10 x64 и Windows-колёса загружены, закреплённые SHA-256 совпали, отдельное окружение собрано.
- Дополнительная офлайн-установка Windows-колёс в тестовый каталог через pip `--no-index --require-hashes --platform win_amd64 --python-version 3.8` проверяет комплектность; Windows-библиотеки при этом не исполняются.
- Статический аудит контракта UI: strict, замечаний нет (`premium-audit.json`). Это не проверка доступности и не замена QtTest.

## Не проверено / ограничения

- Windows 7/8.1/10/11, двойной щелчок `.bat`, UNC-пути, файловые диалоги Проводника, физическое перетаскивание и внешнее открытие файла.
- Несколько отдельных настольных клиентов в одной SMB-папке; сетевые блокировки и реальное отключение соединения. Ошибка связи в QtTest имитируется исключением.
- Длительная нагрузка, очень большие доски/вложения, авария SMB или питания, высокая контрастность и экранный диктор.
- Тестов ролей нет: роли и аутентификация исключены по согласованию. Имя Windows не является доказательством личности.
- Порядок при большом числе вставок между одними соседями может получить равные числовые позиции; стабильное разрешение — ID. Автоматическая перенумерация пока отсутствует.
- Доски/колонки не имеют защиты редактирования по версии; задача имеет. Нет удаления колонок, восстановления досок через интерфейс, удаления вложений, дисковых черновиков и постраничной загрузки.

Перед рабочей эксплуатацией нужен пилот на двух целевых Windows-компьютерах и выбранном файловом сервере, включая резервирование/восстановление и потерю сети. Файловая архитектура согласована пользователем; гарантии серверной архитектуры ей не приписываются.
