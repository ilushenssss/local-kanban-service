# TeamSync

Отдельное настольное приложение Python + PyQt5 для закрытой локальной сети. Без сайта, сервиса, регистрации, облачных API и загрузок при запуске. Роли пока не используются. Автор изменений — имя пользователя Windows.

## Версия 2.1

В 2.1 исправлены открытие обсуждения в конце, возврат на текущую доску, заголовки тёмной темы и сворачивание до одной кнопки «☰». Форма задачи показывает все группы полей без общей вертикальной прокрутки. Колонки получили более контрастные границы.

Справа снизу — кнопка общего чата TeamSync с красным счётчиком непрочитанных сообщений. Нажатие открывает панель переписки сотрудников; «−» сворачивает её, сохраняя черновик. Это общий чат, без личных диалогов и вложений.

**Обновление 2.1:** закройте все клиенты, сделайте резервную копию и обновите программу у всех сотрудников. Первый запуск добавляет таблицу общего чата (схема v2). Предыдущие версии не откроют обновлённую БД. Сохраните `environment/`, `data/` и `kanban.ini`.

Новая компоновка 2.0: единая шапка 56px, переключатель видов, открытые фильтры по исполнителю/стикерам, дерево досок слева, карточки с отдельным рядом стикеров и нижним рядом метаданных. Старые ряды вкладок и нижние кнопки убраны. Шрифт Arial (в Linux — Liberation Sans), 14px; точную исходную гарнитуру по изображениям определить нельзя. Доски с названием «Проект / Доска» группируются в дереве без изменения БД.

Настольный PyQt5-интерфейс переработан: белая сворачиваемая панель, дерево досок, виды «Канбан», «Список», «Диаграмма Ганта», «Сводка». В задаче форма и чат открыты рядом; есть системные события и персональный счётчик непрочитанных сообщений. Новые зависимости не требуются. Проекты отдельной сущностью пока не заведены: дерево группирует существующие доски. Диаграмма Ганта показывает имеющиеся даты без зависимостей.

Доски переключаются вкладками сверху. «Мои задачи» показывает назначения по всем активным доскам с поиском и фильтрами. Карточки и двухколоночное окно задачи переработаны по присланному образцу YouGile.

Во вкладке «Статистика» добавлены графики завершения, распределения по колонкам и нагрузки сотрудников. Точные значения доступны на вкладке «Таблицы». Графики работают без интернета и дополнительных зависимостей.

Обновление доски не пересоздаёт колонки во время перетаскивания и при неизменившихся данных. После переноса загружается актуальное состояние.

Интерфейс с ориентиром на канбан YouGile: цветные заголовки, границы колонок, компактная навигация, дополнительные фильтры под кнопкой «Фильтры». Задачу можно создать прямо в нужной колонке.

- **Колонки → выбрать строку → Удалить колонку…**: выберите, куда перенести задачи, подтвердите и сохраните настройки. Переносятся также архивные задачи; история сохраняется. Последнюю колонку удалить нельзя.
- Метки имеют постоянные автоматические цвета на карточках и в списках выбора.
- Вкладка **Статистика**: все неархивные задачи выбранной доски, завершение, просрочка, распределение по колонкам и сотрудникам. Поисковые фильтры на статистику не влияют.
- Внизу навигации — переключатель **Тёмная тема / Светлая тема**. Выбор сохраняется на компьютере сотрудника.

Перед обновлением закройте приложения у всех сотрудников, создайте резервную копию, сохраните `data/` и `kanban.ini`. Обновите программу на всех рабочих местах.

## Лёгкое обновление — ветка updates

Эта ветка содержит все файлы проекта **кроме папки `environment/` со встроенным Python**. Она предназначена для обновления уже установленного приложения.

[Скачать лёгкий ZIP](https://github.com/ilushenssss/local-kanban-service/archive/refs/heads/updates.zip)

1. Закройте приложение у всех сотрудников и сделайте резервную копию данных.
2. Распакуйте ZIP во временную папку. Откройте внутри папку `local-kanban-service-updates`.
3. Скопируйте **её содержимое** в существующую папку приложения, подтвердив замену файлов. Не удаляйте прежнюю папку приложения и не подменяйте её целиком.
4. Сохраните `environment/`, данные и `teamsync-settings.json`, если он уже создан. При переходе со старой версии сохраните `kanban.ini` до переноса настроек.
5. Запустите приложение прежним ярлыком. Если перенесли приложение в другое место, заново запустите `Create-shortcut.vbs`.

При установке программы отдельно на рабочие места обновите каждое из них. Если программа запускается из одной общей папки, обновите эту папку при закрытых клиентах.

Сообщение «База создана более новой версией программы» означает, что запущенный клиент поддерживает более старую схему. Ограничение доступа сотрудников появилось в схеме v9. Обновите файлы программы из `updates` и проверьте, что ярлык запускает `main.pyw` из обновлённой папки. Сохраните общую базу и её настройки подключения.

**Первая установка:** скачайте [полный ZIP из main](https://github.com/ilushenssss/local-kanban-service/archive/refs/heads/main.zip), распакуйте и запустите `Create-shortcut.vbs`. В main находятся встроенный Python и библиотеки. Лёгкий архив сам по себе не содержит готового окружения для первого запуска.

Ветка updates сейчас использует то же окружение, что main: Python 3.8.10 x64 и PyQt5 5.15.11. Если в будущем изменятся зависимости, сначала потребуется обновить окружение из полной поставки.

## Совместная работа

Можно разместить всю программу в общей папке, например `\\server\Общие\TeamSync`: клиенты запускают встроенный Python оттуда, данные создаются в соседней `data/`. Сотрудникам нужны права чтения/записи/создания/удаления в папке данных.

Или скопируйте программу на каждое рабочее место. В «Настройки → Подключение…» администратор задаёт **один общий UNC-путь** к папке с действующей базой. При запуске из одной общей папки настройка пути едина для всех. Для отдельных копий администратор может разложить созданный приложением `teamsync-settings.json` рядом с `main.pyw`.

SQLite открывается напрямую через общую папку — файловая архитектура согласована пользователем. Запись защищена общей блокировкой и транзакциями; версии задач предотвращают молчаливую перезапись. Но сбои SMB и сети сохраняют риск повреждения SQLite. Требуется надёжная сетевая папка и регулярное резервирование. Не используйте Windows Offline Files, облачную синхронизацию или WebDAV для живой базы.

## Возможности

Общий визуальный контракт интерфейса 2.0 описан в `docs/DESIGN.md`; интерфейс использует единую светлую/тёмную палитру и нативные Qt-контролы.

- Доски: создать, переименовать, архивировать.
- Колонки: названия, порядок, колонка завершения, необязательный лимит с предупреждением.
- Задачи: исполнители, приоритет, метки, срок, описание, чек-лист, комментарии, вложения и история. Перетаскивание и команда «Переместить в…», копирование, архивирование и восстановление.
- Поиск по всей БД, фильтры и обновления коллег без сброса открытой формы.
- Конфликты с сохранением текста, безопасные повторы записи, резервирование SQLite и вложений.

Карточка открывается двойным щелчком. После успешного сохранения карточка закрывается; при ошибке, конфликте или оставшихся неотправленных данных она остаётся открытой.

- **Сотрудники:** кнопка «Сотрудники…» слева или «Справочник…» у исполнителей. Укажите имя пользователя Windows и отображаемое имя; существующему сотруднику можно изменить отображаемое имя. Это не добавляет пароли или роли.
- **Исполнители:** обычный выпадающий список, как в pyqt-desktop. Выберите сотрудника — он появится в списке выбранных под полем. Можно добавить нескольких; для удаления выделите сотрудника и нажмите «Убрать».
- **Метки:** «Метки доски…» добавляет метки в общую БД. В задаче они добавляются обычным выпадающим списком и отображаются под ним. Чтобы снять метку, выделите её и нажмите «Убрать». Метки привязаны к доске.
- **Срок:** компактное поле даты с обычным выпадающим календарём, как в pyqt-desktop. Календарь открывается сразу, без дополнительного флажка. «Сбросить» убирает срок; пустое поле показывает «Без срока». При открытии пустого срока календарь показывает текущий месяц, отмена выбора не назначает дату.
- **Чек-лист:** введите пункт и нажмите «Добавить» или Enter. Отмечайте выполненное флажками; двойной щелчок редактирует текст. «Убрать пункт» удаляет выбранный пункт до сохранения. Текст в поле нового пункта также включается при сохранении задачи.
- **Приоритет:** низкий — серый, обычный — синий, высокий — янтарный, срочный — красный; подпись всегда видна, поэтому значение определяется не только цветом.
- **История:** автор, дата и понятные названия изменённых полей с прежними и новыми значениями. Время показывается в часовом поясе команды (по умолчанию UTC).

При создании задачи нет поля «Переместить в…»: новая задача попадает в первую колонку доски. Перемещение доступно для сохранённых задач. Для комментариев и вложений сначала сохраните задачу, затем откройте её снова. Одинаковые имена вложений не приводят к замене файлов.

Для обновления закройте приложение у всех сотрудников, сделайте резервную копию и замените файлы программы. Сохраните свою папку `data/` и `kanban.ini`; архив GitHub их не содержит. Справочники используют существующие таблицы `users` и `labels`, новую базу создавать не нужно.

## Что входит

```text
Create-shortcut.vbs    создание ярлыка на рабочем столе
main.pyw               точка входа
kanban/                код приложения
environment/python/   сохраняется от полной установки main; в ветке updates отсутствует
teamsync-settings.json  путь к базе, создаётся через настройки
requirements/          закреплённые версии зависимостей
docs/                  инструкции и результаты проверок
tools/                 обслуживание и воспроизводимая сборка
tests/                 автоматические проверки
```

Встроено: Python 3.8.10 x64, PyQt5 5.15.11, Qt 5.15.2, PyQt5-sip 12.15.0 — по образцу ветки `pyqt-desktop`. Из Qt оставлены Core, Gui, Widgets и Test для проверок; лишние модули, инструменты сборки Python и посторонние приложения удалены. Сохранены необходимые DLL, платформенные плагины и лицензии. Условия лицензирования зависимостей находятся в окружении; PyQt5 распространяется по GPL/commercial.

Целевые ОС — Windows 10/11 x64. Окружение выбрано также для совместимости с Windows 7 SP1/8.1 x64 (нужны KB2533623 и KB2999226), но запуск в Windows здесь не проверялся. Python 3.8 выбран по образцу, несмотря на завершение его поддержки.

## Обслуживание и разработка

[Резервирование, восстановление и обновление](docs/OPERATIONS.md) · [Архитектура](docs/ARCHITECTURE.md) · [Проверки и ограничения](docs/VALIDATION.md).

При аварии не удаляйте `kanban.lock` по возрасту: администратор сначала закрывает все клиенты и проверяет, что запись нигде не идёт. Не удаляйте журналы SQLite. При конфликте используйте сравнение версий в карточке. Несохранённые данные остаются в открытой форме, но не переживают аварийное закрытие приложения.

Пересборка окружения выполняется **только разработчиком на компьютере с интернетом**, не при обычном запуске: `python tools/build_windows.py`. Все загружаемые пакеты проверяются по закреплённым SHA-256. Перед пересборкой сохраните старое `environment/python` вне репозитория: скрипт не заменяет существующую папку. `tools/trim_windows.py` оставляет нужные модули. Дополнительный ZIP: `python tools/package_windows.py NEW_ARCHIVE.zip`.

Проверки Windows:

```text
environment\python\python.exe -m unittest discover -s tests -v
```

Проверки Linux (отдельное окружение, не Windows-библиотеки):

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements/runtime.txt
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
```

Новые доски из интерфейса получают колонки «Бэклог», «В работе», «На проверке», «Готово». Колонки существующих досок сохраняются.

Приложение называется TeamSync. После обновления запустите `Create-shortcut.vbs`, чтобы создать ярлык «TeamSync». Старый ярлык «Канбан» можно удалить вручную. Рабочую папку и существующий `kanban.ini` переименовывать не нужно.

## Роли и доступ — схема v3

Три роли: единственный администратор, менеджер, сотрудник. Менеджер создаёт доски и задачи и выдаёт доступ к своим доскам. Сотрудник меняет существующие задачи доступных досок. Первого администратора необходимо назначить явно в существующей базе; автоматически им никто не становится.

**Перед обновлением закройте все клиенты и сделайте резервную копию.** После обновления настройте администратора и доступ к прежним доскам по [инструкции](docs/ACCESS.md). Обновить нужно все клиенты: прежние версии не поддерживают новую схему. Сохраните `environment/`, данные и `kanban.ini`.

## Фотостикеры в общем чате — схема v4

В общем чате нажмите **«Фотостикер…»**, выберите PNG/JPG/WebP, проверьте предпросмотр и нажмите **«Отправить стикер»**. Изображение из буфера можно вставить через Ctrl+V в поле сообщения. Текстовый черновик сохраняется. Нажатие на стикер открывает увеличенный просмотр.

Исходный файл — до 10 МБ и 25 миллионов пикселей. Изображение сохраняется как статический PNG не больше 512×512 с сохранением пропорций и прозрачности; в чате показывается до 180×180. Анимация не сохраняется, фон автоматически не удаляется. При сбое нажмите «Повторить стикер»: отправка использует прежний идентификатор и не создаёт дубликат. До подтверждения отправки заменить стикер нельзя.

Обновление: закройте все клиенты, сделайте резервную копию и обновите содержимое программы у всех сотрудников, включая `kanban/qt_plugins/` (Windows WebP-кодек). Сохраните `environment/`, данные и `kanban.ini`. Первый запуск обновляет схему до v4; роли и администратор сохраняются, повторно назначать администратора не нужно. Старые версии со схемой v3 не откроют обновлённую базу. Новые backup/restore включают стикеры вместе с остальными вложениями.

## Уведомления и орфография

При новом сообщении общего чата TeamSync показывает уведомление рабочего стола, даже если окно свёрнуто или скрыто в трее. Нажатие на уведомление или значок в трее открывает общий чат. Уведомления о старой переписке при запуске, своих сообщениях и сообщениях при активном открытом чате не показываются. Несколько сообщений подряд объединяются. Для фотостикера показывается «Отправил фотостикер».

Если системный трей доступен, крестик по умолчанию скрывает окно в трей: приложение продолжает работать и проверять сообщения. Полностью завершить работу можно через **правый щелчок по значку TeamSync → Выйти из TeamSync**. При незавершённых операциях выход блокируется, при неотправленном сообщении/стикере или несохранённой форме требуется подтверждение. Если трей недоступен, крестик закрывает приложение как раньше. После полного выхода уведомлений нет.

В «Настройках» и меню трея доступны переключатели **«Уведомления общего чата»**, **«Закрывать окно в трей»**, **«Проверять орфографию»**. Настройки локальны для пользователя Windows. Вид, звук и разрешение системных уведомлений регулирует Windows; политики Windows Server/RDP могут ограничивать их показ. Уведомления относятся к рабочему столу сеанса, в котором запущен TeamSync.

Проверка русского и английского текста работает офлайн в названии/описании задачи, обсуждении задачи, общем чате, именах в справочниках и чек-листе. Опечатки подчёркиваются красной волнистой линией; автозамены нет, сохранённый текст и история отмены не меняются. Словоформы поддерживаются. Адреса сайтов, email, короткие аббревиатуры и цифровые идентификаторы пропускаются. Словари могут не знать имён, терминов и новых слов; грамматика и пунктуация не проверяются. После первого открытия поля словари загружаются в фоне, затем подчёркивание появляется автоматически.

Для обновления скопируйте всё содержимое updates, включая `kanban/_vendor/` и `kanban/dictionaries/`. Новых установок через pip, интернет-доступа или переназначения администратора не требуется; схема БД остаётся v4.

## Чаты досок и управление метками — схема v5

Нижний правый чат теперь относится к выбранной доске. У каждой доски своя переписка, фотостикеры, непрочитанные сообщения и черновик. При переключении доски текст/предпросмотр и безопасные повторы остаются в исходном чате. Без выбранной доски отправка недоступна. Читать, писать и загружать стикеры могут только пользователи с доступом к этой доске. Уведомления поступают с доступных досок, включая невыбранные; нажатие открывает доску последнего сообщения.

**Прежняя общая переписка переносится на активную доску «С-А»** вместе со стикерами и отметками прочтения. Если активной доски с таким точным названием нет, миграция создаёт её и передаёт администратору; затем администратор настраивает участников. Переписка не дублируется на остальных досках. Если несколько активных досок имеют имя «С-А», перед обновлением оставьте это имя у одной. Перенос выполняется один раз.

В **«Настройки → Метки доски»** теперь доступны **«Переименовать»** и **«Удалить»**. Это может делать администратор или менеджер — владелец доски. Переименование сохраняет назначения; удаление с подтверждением снимает метку со всех задач доски, включая архивные. История задач сохраняется, старые открытые формы получают конфликт версии. Удалённая метка не восстанавливается автоматически из устаревшего черновика. Создать её заново можно явно через «Добавить».

Перед обновлением закройте все клиенты и сделайте резервную копию, затем обновите файлы у всех сотрудников. Сохраните environment/, данные и kanban.ini. Схема повышается до v5: старые клиенты v4 откажутся открывать базу. Роли и администратор сохраняются.

## Личное — схема v6

В левой панели появился раздел **«Личное»**. Нажмите **«＋ Создать доску»** внутри этого раздела, введите название — откроется ваша личная доска. Создавать её может любой сотрудник независимо от общей роли.

Владелец может создавать, редактировать, перемещать и архивировать задачи, управлять колонками и метками, добавлять комментарии и вложения, переименовывать и архивировать доску. Настройки находятся в том же меню, что и у рабочих досок. Вернуть архивированную доску можно через **«Личное → Архив личных досок…»**. Исполнителем личной задачи может быть только её владелец; поле можно оставить пустым.

Другие пользователи, включая администратора, не видят личные доски через приложение и не могут открыть их задачи, вложения и чат по ID. Принадлежность к board_members не открывает личную доску. Выдача доступа и смена владельца для неё запрещены. «Мои задачи» и уведомления используют ту же фильтрацию. Рабочие доски и правила ролей для них сохраняются; смена роли не меняет владельца личных досок.

**Граница приватности:** личные доски остаются в общей SQLite-базе и входят в административные резервные копии. Технический доступ к файлам БД/вложений и возможность запуска изменённого клиента позволяют обойти ограничения приложения. Идентификация сохраняет прежний Windows login; общая учётная запись означает одного пользователя. Для изоляции от прямого файлового доступа потребуется другая архитектура хранения/авторизации.

Перед обновлением закройте все клиенты, сделайте резервную копию и обновите программу у всех сотрудников. Сохраните environment/, данные и kanban.ini. Миграция v6 оставляет все прежние доски рабочими, данные и роли сохраняются. Старые клиенты v5 новую базу не откроют; администратора переназначать не нужно.

## Уведомления об изменениях задач — схема v7

Исполнители и создатель задачи получают системные уведомления о назначении/снятии назначения, смене статуса, срока, приоритета, названия, описания, меток, чек-листа, архивировании/восстановлении, новых комментариях и вложениях. При смене исполнителей уведомляется также прежний исполнитель, если у него остаётся доступ к доске. Собственные действия, сохранение без изменений и простая перестановка карточек внутри колонки не вызывают уведомлений. Остальные участники доски уведомления о чужих задачах не получают.

Нажатие на уведомление открывает карточку задачи, даже с другой доски. Если карточка уже открыта, она получает фокус без потери несохранённых правок. Проверки доступа учитывают личные доски и повторяются перед показом уведомления и открытием карточки. После отзыва доступа или архивирования доски новое уведомление не показывается.

Несколько событий подряд объединяются; уведомление показывает последнее событие и открывает соответствующую задачу. При временном сбое сети проверка повторяется. Первый успешный опрос после запуска задаёт начальную точку без всплывающих уведомлений о прежней истории. Это уведомления работающего приложения, отдельного центра уведомлений внутри TeamSync пока нет. После полного выхода из приложения уведомлений нет.

Настройка **«Уведомления об изменениях задач»** находится в меню настроек и меню значка в трее, включена по умолчанию и независима от уведомлений чатов. Вид и звук задаёт Windows; Windows Server/RDP может ограничивать показ.

Перед обновлением полностью выйдите из TeamSync у всех сотрудников через меню значка в трее, сделайте резервную копию и обновите программу на всех рабочих местах. Сохраните environment/, данные и kanban.ini. Схема v7 сохраняет задачи, историю, роли и личные доски, старые клиенты v6 новую базу не откроют. Администратора переназначать не нужно.

## Счётчики уведомлений у досок

В левой панели рядом с каждой доской показывается красный счётчик: непрочитанные сообщения чата доски плюс уведомления по её задачам. Группы досок показывают сумму, поэтому новые события видны и при свёрнутой группе. При наведении видна разбивка **«Чат: … · Задачи: …»** и полное название доски. Для больших значений отображается 99+, точное число остаётся в подсказке.

Счётчики обновляются примерно раз в 3 секунды, независимо от включения системных всплывающих уведомлений. Переключение доски само по себе их не сбрасывает. Чат читается при открытом активном окне и прокрутке до конца; уведомления задачи — при открытии/активации её карточки и загрузке соответствующей истории. Свёрнутое или неактивное окно не отмечает задачу прочитанной. После чтения карточки уведомления по ней не всплывают повторно из уже загруженной очереди.

Отметки хранятся для каждого пользователя в общей БД и сохраняются после перезапуска. Новое событие, записанное после загруженного снимка карточки, не снимается старой отметкой. Чужие личные, архивные и недоступные доски не участвуют в подсчёте. При первом обновлении могут отображаться прежние уведомления задач: отметок их прочтения в предыдущей версии не было. Схема БД остаётся v7, роли и данные сохраняются.


## Redmine на проектной доске

Для ветки `updates-redmine` администратор установки добавляет в окружение TeamSync пакеты из `requirements/redmine.txt`. Для портативной поставки Windows из корня программы выполните обычным Python с pip:

```powershell
py -m pip install --only-binary=:all: --platform win_amd64 --implementation cp --python-version 3.8 --abi cp38 --target environment/python/Lib/site-packages -r requirements/redmine.txt
```

Откройте **Настройки → Подключение…** под учётной записью администратора базы. Укажите папку с `kanban.db`, адрес Redmine с http:// или https:// и при необходимости соответствия статусов колонкам по одному на строку, например `Новый = Проект ТИ`. Если в базе уже настроен Redmine, первичное подключение сохраняет эти параметры. После подключения администратор может изменить их в той же форме.

Путь сохраняется в `teamsync-settings.json` рядом с программой. Для сохранения пути нужны права записи в папку установки. Сотрудникам достаточно чтения и запуска программы. При смене папки базы полностью перезапустите TeamSync. Для новой установки администратор сначала подготавливает базу и назначает первого администратора через tools/init_admin.py с флагом --create. При обновлении с прежней версии окно может подставить значения из старого `kanban.ini`. После сохранения TeamSync загружается без него.

Во вкладке «Текущие работы» менеджер или администратор нажимает верхнюю кнопку «Добавить задачу» и вводит числовой ID задачи из адреса Redmine. При первом запросе TeamSync просит логин и пароль. Вход действует до полного выхода из приложения. Кнопка «Обновить по #ID» читает только уже добавленные задачи по их Redmine ID и обновляет данные карточек. «Настройки → Обновить» на этой вкладке выполняет ту же операцию. Если статус не сопоставлен с колонкой, TeamSync показывает ошибку. При обновлении такой карточки сохраняется последняя успешно сохранённая версия.

Администратор задаёт источник массовой загрузки отдельно для каждой проектной доски через «Настройки → Проект СППИ…». Имя проекта должно быть ключом в `all_project.json`. Ранее сохранённое общее значение применяется к доскам без своей настройки. Пустое значение отключает выгрузку СППИ для выбранной доски. Рядом с `main.pyw` разместите `employees.json` со списком ФИО или логинов Redmine, например `["Иванова Анна", "petrov"]`. Кнопкой «Выгрузить из Redmine» менеджер или администратор запускает проверку задач этого проекта. TeamSync получает пользователя и версию по ID из полей «Ответственный за выпуск ТИ» и «Приоритет реализации» и добавляет карточки при совпадении сотрудника и названия доски с данными версии. Подзадачи доступны в окне карточки. Выгрузка добавляет недостающие и обновляет уже загруженные карточки по ID. Массовая выгрузка начинает с задач без родителя. Для подходящей ТИ её доступные прямые и вложенные подзадачи добавляются отдельными карточками по собственным ID. Подзадача также может пройти фильтры самостоятельно. Если подзадача загружается вместе с родительской ТИ и для её статуса нет колонки, используется колонка родительской ТИ. Карточки появляются по мере загрузки. Задачи со статусом «ТИ закрыто» пропускаются. Во время выгрузки внизу вкладки видны до четырёх последних проверенных ТИ с ID, ответственным и версией. После выгрузки журнал очищается.

При добавлении и обновлении карточки TeamSync читает пользовательские поля Redmine с фразой «ТИ согласовано с» или «ТИ согласовано со» в названии. Остаток названия отображается на карточке. Для «Нет» и «На согласовании» плашка красная, для «Есть замечания» жёлтая, для «Да» зелёная. Поля со значением «Не требуется» скрыты.

Значения поля «Основание для открытия ТИ» отображаются в строке «Основание», а значения поля «№ bz» — в строке «Баги». Запятые и переносы строк разделяют значения на отдельные плашки. Пробелы внутри значений сохраняются.

Администратор задаёт проект для проверки оснований в меню проектной доски «Настройки → Проект поиска оснований…». Название должно совпадать с ключом из `all_project.json`. При добавлении ТИ и через «Настройки → Обновить» TeamSync ищет номера вида «ТИ(200)-1234-56» в поле «Регистрационный номер_ЛПИВ» задач выбранного проекта. Текст после номера отсекается. Зелёная плашка означает «ТИ утверждено», красная — другой статус, серая — статус не получен. Результат проверки сохраняется в общей базе и доступен участникам доски.

На вкладке «ИД» кнопка «Обновить из Redmine» загружает задачи проекта поиска оснований с полем «ТИ согласовано с отд.ЦЗ». Значение «Не требуется» исключает задачу. «Да» подсвечивается зелёным, «Нет» — красным. Карточки распределены по четырём колонкам по связи с ТИ и статусу утверждения. Зелёная полоска сверху означает «ТИ утверждено», красная — другой статус. Внизу карточки перечислены ТИ, где этот номер указан в основании, по доступным пользователю доскам. При отсутствии связей отображается «Не привязано». Загруженные карточки доступны участникам доски из общей базы.

Вкладка «ИД» показывает ТИ(200), если название хотя бы одной версии из поля «Приоритет реализации_ЛПИВ» содержит название текущей доски. Например, версия «2.0-218 И-01» подходит для доски «2.0-218». Если подходящая версия отсутствует или недоступна в Redmine, карточка скрыта. Чтобы получить версии для ранее загруженных карточек, обновите вкладку из Redmine.

Для поиска КРИС_ТИ положите `all_project.json` рядом с `main.pyw`. Ключи должны точно совпадать с названиями проектов в папке «Проекты». Значение каждого ключа — числовой ID соответствующего проекта КРИС_ТИ в Redmine. Например:

```json
{
  "Разработка": 49,
  "Внедрение": 73
}
```

TeamSync ищет в указанном проекте Redmine первую открытую верхнеуровневую задачу с ID исходной ТИ в поле «Расположение ТИ». На карточке отображается доля прямых подзадач, у которых название статуса содержит «Выполнено», включая закрытые подзадачи. Из расчёта исключаются подзадачи со статусом «Действие не требуется». Если совпадения нет, отображается прочерк. При ошибке чтения или отсутствующем сопоставлении сохраняется последний прогресс.

В окне ТИ раздел «Согласование приложений» показывает прямые подзадачи КРИС_ТИ с названием, исполнителем и статусом. Из названия убирается заголовок родительской КРИС_ТИ. Чтобы заполнить таблицу для ранее загруженных карточек, нажмите «Обновить по #ID».

Под прогрессом выводятся сроки из поля `due_date` задач КРИС_ТИ в статусе «Кодирование». При общей дате отображается «Кодирование до ДД.ММ». Разные сроки выводятся по названиям подзадач. Если таких подзадач нет, TeamSync показывает срок самой задачи КРИС_ТИ, когда она в статусе «Кодирование».

В заголовке карточки ТИ отображается название связанной основной задачи КРИС_ТИ. Пока это название недоступно, отображается имя трекера ТИ. Рядом отображаются инициалы ответственного за выпуск ТИ. У подзадачи отображаются инициалы ответственного её родительской задачи. Внутри колонок ТИ отсортированы по номеру, а редакции идут вслед за основной ТИ в порядке номера редакции.

В колонке «ТИ открыто» шеврон или клавиша Пробел сворачивает выбранную карточку до полоски с заголовком и сроком кодирования. При разных сроках полоска показывает диапазон дат, а подсказка — сроки по подзадачам. Шеврон или Пробел снова разворачивает карточку. Enter открывает задачу. Состояние сворачивания сохраняется при обновлении доски в текущем сеансе.

Круговая стрелка в правом верхнем углу карточки ТИ или ИД обновляет эту карточку из Redmine. С клавиатуры выберите карточку и нажмите Ctrl+R.

Название КРИС_ТИ, ID задачи, заголовок, статус, согласования, СП, номера багов и прогресс КРИС_ТИ видят все участники доски, даже если у них нет доступа к этой задаче в Redmine. Это данные общей SQLite. Пароль хранится только в памяти процесса и не записывается в общую базу. Redmine получает только запросы чтения. При HTTP пароль и данные передаются без шифрования. Используйте HTTPS, если он доступен.

Менеджер с доступом к доске или администратор может убрать ошибочно добавленную ТИ через «Убрать с доски» в контекстном меню или окне карточки. Действие убирает привязку в TeamSync. Сама задача остаётся в Redmine. Действие доступно для ручных карточек и старых карточек с неизвестным источником.

Перед обновлением завершите все клиенты и сделайте резервную копию. Схема v15 сохраняет источник добавления карточки Redmine. Клиенты v14 и ниже не смогут открыть базу после миграции.

## Выгрузка бага из Bugzilla

Администратор задаёт адрес Bugzilla и почтовый домен через **Настройки → Подключение…**. Например, адрес `https://bugs.example.org/bugzilla` и домен `example.org`.

В **Настройки → Выгрузить баг из Bugzilla…** введите числовой ID бага и пароль Bugzilla. TeamSync добавит `@` и настроенный домен к имени пользователя Redmine. До первого входа в Redmine используется имя пользователя TeamSync, которое по умолчанию подставляется и в форму входа Redmine. Запрос `Bug.get` через `POST /xmlrpc.cgi` возвращает данные бага. Кнопка **Сохранить JSON…** записывает их в выбранный файл.

После успешной выгрузки пароль Bugzilla остаётся в памяти до выхода из TeamSync. Повторный ввод потребуется после отказа во входе или смены адреса, домена либо пользователя. В общей базе хранятся адрес и домен. При адресе с HTTPS данные передаются зашифрованными.

На проектной доске вкладка **Баги** принимает выгрузку по ID и массовую выгрузку по кнопке **Выгрузить по фильтрам**. При массовой выгрузке `product` должен содержать название проекта, `version` — название доски, а `assigned_to` — хотя бы одну строку из `employees.json` рядом с `main.pyw`. При выгрузке по ID применяется фильтр по `assigned_to`. Сравнения выполняются без учёта регистра.

При массовой выгрузке таймаут подключения составляет 10 секунд, ожидания ответа — 60 секунд. Сообщение о таймауте указывает метод Bugzilla и этап запроса.

В колонку **Привязаны** попадают баги, номер которых есть в поле **Баги** любой ТИ в «Текущих работах» этой доски. Остальные отображаются в колонке **Не привязаны**. Карточка показывает номер, `summary`, **Дальнейшее действие** (`cf_event_1`) и **ТИ** (`cf_cr_num`). Успешная массовая выгрузка заменяет набор карточек на текущей доске.

Карточки сохраняются в общей базе TeamSync и видны участникам соответствующей доски. Для просмотра карточек достаточно доступа к доске. Для выгрузки и обновления используется личная учётная запись Bugzilla. Кнопка **Обновить** запрашивает только сохранённые ID. Баг с отказом в доступе при обновлении сохраняет прежние данные в общем списке. Чтобы опубликовать ранее сохранённые локальные карточки, нажмите **Обновить** или **Выгрузить по фильтрам**.
