# Канбан — настольное приложение

Самостоятельное приложение на Python и PyQt5 для закрытой локальной сети. Не связано с журналом служебных записок. Нет сайта, Electron, облачных API, телеметрии или ИИ. При запуске ничего не скачивается.

По согласованному изменению требований используется **файловая архитектура без сервиса и ролей**: клиенты работают с `kanban.db` и каталогом вложений в общей папке. Пользователь определяется по имени учётной записи Windows. Это подпись в истории, а не проверенная аутентификация. Права на папки задаёт администратор Windows.

## Быстрый запуск Windows без интернета

Готовая поставка должна содержать `environment/python/` (Python 3.8.10 x64 с PyQt5). Git содержит исходники и скрипты подготовки. Переносное окружение и wheelhouse в Git не хранятся; архив Code → Download ZIP сам по себе не является готовой офлайн-поставкой. Для сборки окружения на машине с интернетом выполните `python tools/build_windows.py`. Скрипт скачивает только официальные пакеты и сверяет закреплённые SHA-256; повторную сборку поверх существующего окружения запрещает.

1. Скопируйте готовую папку приложения на рабочее место, например `C:\Kanban`, или в общую папку программы. Установщик Python не нужен.
2. На файловом сервере создайте отдельную папку данных, например `\\server\Общие\Канбан\data`. Дайте сотрудникам права чтения, создания, изменения и удаления файлов в ней. Каталог программы можно оставить только для чтения.
3. Скопируйте `kanban.ini.example` в `kanban.ini` и задайте один и тот же UNC-путь к данным у всех клиентов. Сохраните INI как UTF-8. Без INI используется локальная `data/` рядом с программой — только для ознакомления.
4. Откройте `Kanban.bat` двойным щелчком. Для диагностики — `Kanban-console.bat`. Ошибки Python: `%TEMP%\kanban-errors.log`.
5. Создайте доску; пять начальных колонок появятся автоматически.

Из UNC-каталога cmd может вывести своё стандартное предупреждение о рабочем каталоге. Скрипт использует абсолютные пути и от него не зависит. Служба на сервере, порт и интернет не нужны.

Окружение выбрано по образцу `electronic-document-management-system/pyqt-desktop`: Python 3.8.10, PyQt5 5.15.11, Qt 5.15.2, PyQt5-sip 12.15.0. Целевые системы — Windows 10/11 x64; совместимость с Windows 7 SP1/8.1 x64 предусмотрена выбором окружения (KB2533623 и KB2999226), но **не проверена**. Python 3.8 больше не получает исправлений безопасности; эта версия выбрана для совместимости с указанным образцом. Перед эксплуатацией нужна проверка на реальных рабочих местах. Условия лицензий PyQt5 (GPL/commercial) и Qt входят в поставку зависимостей; организация выбирает подходящий режим распространения.

## Альтернативная установка в venv без интернета

На компьютере с интернетом подготовьте Windows-колёса командой `python tools/build_windows.py` (каталог `wheelhouse/`). Перенесите его, исходники и официальный установщик Python 3.8.10 x64 в закрытую сеть. На рабочем месте заранее установите Python с launcher `py`, затем дважды щёлкните `Install-offline.bat`. Он создаёт `.venv` и устанавливает только закреплённые колёса из локального каталога с проверкой хешей. `Kanban.bat` использует переносное окружение, если оно есть, иначе `.venv`.

Не переносите Linux-venv на Windows. Для закрытой сети заранее подготовьте отдельную офлайн-поставку с проверенными бинарными зависимостями. Исходный архив GitHub их не содержит.

После подготовки окружения создайте готовый ZIP командой `python tools/package_windows.py Kanban-Windows-x64.zip`. Этот архив распространяется отдельно от исходников; при наличии доступа его можно прикрепить к GitHub Release.

## Работа

- Доски: создание, переименование, архивирование. Архивированная доска скрывается у всех.
- «Колонки…»: названия, порядок кнопками «Выше/Ниже», добавление, одна колонка завершения, необязательный лимит. Превышение обозначается текстом и не запрещает работу. Удаление колонок не предусмотрено.
- Карточка открывается двойным щелчком или кнопкой. Название обязательно; исполнители и метки вводятся через запятую. Имена исполнителей — имена пользователей Windows; отдельного справочника входа нет.
- Срок — `ГГГГ-ММ-ДД`, пустое поле убирает срок. Хронология хранится и отображается в UTC; просрочка определяется по локальной дате компьютера. Синхронизируйте часы рабочих мест.
- Чек-лист: одна строка на пункт, `[ ]` — не выполнено, `[x]` — выполнено.
- Карточки переносятся перетаскиванием (перед карточкой под указателем, внизу — в конец) либо через «Переместить в…». Изменение порядка сохраняется. Выход из завершающей колонки очищает дату завершения.
- «Копировать» открывает новую несохранённую задачу с полями и чек-листом исходной. Комментарии, вложения и история не копируются.
- «Архив» в фильтрах показывает архивные задачи; «Архивировать / восстановить» меняет состояние выбранной задачи.
- Поиск по названию/описанию не чувствителен к регистру, в том числе русскому. Фильтры исполнителя и метки — по точному имени. Все фильтры выполняются по БД, а не по загруженным карточкам. Показаны все найденные задачи; постраничной загрузки в этой версии нет. Ориентир — отдел и умеренные доски.
- Вложения: сначала сохраните задачу, затем выберите файлы или перетащите из Проводника во вкладку. Одинаковые исходные имена допускаются, внутренние имена уникальны. «Скачать как…» не перезаписывает существующий файл. «Открыть» выгружает проверенную копию в `%TEMP%/kanban-*` и передаёт установленной программе. Временные копии можно удалить после закрытия внешних редакторов. Правки открытой копии не обновляют вложение автоматически.

## Сеть, конфликты, повторы

БД использует DELETE-journal, FULL synchronous и внешние ключи; WAL на сетевой папке не используется. Все изменения проходят через атомарный `O_EXCL`-файл `kanban.lock`, затем транзакцию SQLite. История задачи и изменение записываются вместе. Не редактируйте БД сторонними средствами при открытых клиентах.

Версия задачи проверяется при записи. Конфликт не уничтожает текст: доступны сравнение и явное принятие текущей версии как основы; перед повторным сохранением вручную согласуйте поля. Автоматического слияния нет. Открытые карточки не перезаписываются фоновым обновлением; комментарии, вложения и история обновляются каждые пять секунд.

Работа с хранилищем и файлами идёт в пуле потоков, вне потока интерфейса. При ошибке данные остаются в открытой форме. Сохранение задачи, комментарий и вложение повторяются с прежним идентификатором: повтор после неопределённого результата не создаёт дубликат. Для операций главного окна есть «Повторить запись». Не меняйте данные неопределённой операции перед повтором. Закрытие формы предупреждает о потере текста и состояния повтора. Черновики и идентификаторы повтора не переживают аварийное завершение приложения; полноценного офлайн-редактирования нет.

При аварии блокировка **не снимается автоматически по возрасту**: медленный писатель может оставаться активным. Администратор должен закрыть все клиенты, проверить, что запись и резервирование нигде не идут, сохранить копию данных и только затем удалить `kanban.lock`. Он содержит имя, компьютер, PID и время владельца. Не удаляйте файлы SQLite `-journal`: они могут быть нужны для восстановления.

SMB-сервер должен поддерживать корректные файловые блокировки и атомарное создание файлов. Не используйте синхронизируемые облаком, автономные Windows Offline Files, WebDAV или реплицируемые папки для живой БД. Файловая архитектура по согласованию с заказчиком сохраняет риск повреждения SQLite при сетевых сбоях и ошибках SMB; блокировка приложения не заменяет гарантии файловой системы. Проверьте инфраструктуру и восстановление до начала рабочей эксплуатации.

## Резервирование, восстановление, обновление

См. [инструкцию администратора](docs/OPERATIONS.md). Копия создаётся через `SQLite.backup()`, проверяется `integrity_check` и `foreign_key_check`, затем отдельно копируются и проверяются вложения. Срок хранения по умолчанию — 14 дней. Для автоматического запуска предусмотрен CLI и пример задания Windows Task Scheduler.

## Разработка и проверки

```sh
python -m venv .venv
.venv/bin/python -m pip install -r requirements/runtime.txt
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m kanban
```

На Windows команды выполняются через `.venv\Scripts\python.exe`, `QT_QPA_PLATFORM` задавать не нужно. Тесты используют стандартный `unittest` и QtTest из PyQt5; дополнительных пакетов тестирования нет.
